用户要求：完成这轮 GPU / 外观改造剩余的所有非性能事项，先写计划，复审通过后执行。性能排查暂停。

## 4. 技术决策

### 4.1 用独立新主题交付 v4，保留原 GPU 玻璃

新增 `resources/themes/LiquidGlass_Toolbar_GPU.json`，显示名为“浮动轻雾玻璃”。现有 `LiquidGlass_GPU.json` 和 `CyberPunk_GPU.json` 不因本轮新观感被覆盖。

新主题继续使用 `material=liquid_glass`，通过明确的样式参数 `glassStyle=floatingToolbar` 选择 v4；字段缺省保持现有路径。冻结时校验字符串枚举、非法类型和未知值的明确回退。所有样式参数仍通过现有主题模型、运行时映射、常量缓冲区与共享 shader 下发，不按主题文件名猜测后端。

v4 的正式面板和编辑器使用同一份材质代码、常量、采样规则；固定背景、固定时间和固定数据可以替换输入，材质不能各自分叉。独立样板保留为历史参考；如继续提供可运行预览，应调用共享材质入口，避免维护第三套“近似生产”的实现。

### 4.2 模糊和几何单位统一

采样偏移从调用方到 `DesktopUv` 全链路只保留一种约定：**物理像素**，在最终纹理 UV 计算处除以实际输入纹理尺寸一次。固定纹理也使用明确的尺寸与原点，不假定为当前屏幕大小。

DPI/UIScale 在主题逻辑尺寸进入渲染帧常量时转换一次；已有物理坐标不得重复缩放。新样式的圆角、边缘、雾半径和阴影随缩放规则明确，客户区、窗口 Region、玻璃外形和捕获裁切一致。横向窄面板圆角不超过半短边，所有几何覆盖来源于真实布局。

修复 live blur 是刻意的缺陷修正，旧实时路径的受影响像素允许变化；固定输入旧 GPU 路径和全部旧 GDI+ 主题应维持原图。不能因旧实时截图未保持而撤回正确的单位修复，也不能把所有差异都归因于此。

### 4.3 前景与可读性

保留业务布局、所有选中指标、缺失值、告警色和进度值；禁止复制样板固定数值进入生产。新样式用与 v4 匹配的浅玻璃深色前景，颜色由明确的样式/主题输入选择，不全局改变赛博或旧玻璃配色。

进度条生产路径只绘制对齐的轨道与填充，不移植独立样板的 18×1px 开头装饰。文字与条形在前景阶段绘制，不参与背景折射。不同明暗背景下核对可读性；若需要保护文字，采取局部且明确的处理，不擅自加重整块玻璃雾化。

字体/字号/颜色仍属主题前景输入，不是 shader 浮点参数。N01 必须冻结它们从主题到运行时前景快照、生产画笔/字形、编辑器预览的映射；仅用 `MaterialKind.LiquidGlass` 选择一套硬编码浅字或深字不算接线完成。新样式实际消费主题 font/color 和用户缩放，并保留缺字回退、缺失值及告警色语义。旧 GPU 样式的默认外观保持；若现有编辑器提供了实际不生效的字段，必须明确修复映射或在对应旧路径禁用并说明，不能继续假装字段已生效，也不能借此禁用新样式的字体/颜色编辑。修复导致的既有 GPU 前景差异逐项留证，不静默覆盖期望图；旧 GDI+ 像素要求不变。

### 4.4 常量 ABI 与源码快照

- N01 记录每个 C# 常量字段对应的 HLSL 槽位、字节偏移、16 字节对齐与总大小；新增样式槽位不得覆盖现有 motion/state。添加尺寸/偏移断言与正式 shader 编译检查，并在生产与编辑器复用同一组常量构造。
- N00 先记录完整生产输入清单（含本轮之外已存在的硬件/网络源码，不把其所有权归入本轮），本轮改动只写分配范围。
- N10 创建新的只读候选源目录：拷贝前/后分别扫描源文件、项目文件、主题、资源和构建脚本哈希，并验证候选副本内容与两次扫描一致。发生并发改动则重建候选快照，不能把不同时间的文件拼成一次已验版本。最终从该候选副本统一构建和打包；工作目录后续变化不自动进入已冻结候选。
- 报告同时记录 baseline HEAD、源码清单哈希和二进制哈希；不得用未提交工作区的 HEAD 代替实际源码身份，也不得发布旧 DLL。其他 owner 的新变化需要进入候选时先重新冻结，并重跑受影响验收。

### 4.5 固定纹理的真实输入接口（N01/N02 必交付）

现有固定模式实际是 shader 程序背景，不是可注入图片；不能只修改 UV 就声称支持 v4 图像回放。

- 冻结 `FixedBackgroundInput` 等价输入合同：BGRA8 数据/纹理、实际宽高、物理原点和覆盖矩形、内容版本/哈希、SDR 格式、资源所有权和失效条件。
- renderer 新增可选固定输入上传/绑定入口，生产与预览使用同一入口。固定输入的设备资源由 renderer 持有并纳入账本，替换/尺寸改变/失败/Dispose 时释放；输入缓冲区不可在渲染过程中被外部改写。已有调用不提供固定输入时，保持程序背景作为明确默认模式。
- 区分 `procedural / fixedTexture / liveCapture` 的实际输入模式；固定纹理采样不得伪造 live 状态、创建捕获源、改变 affinity 或沿用实际桌面尺寸。增加诊断字段记录模式、输入哈希、尺寸、原点和覆盖矩形。
- N02 把 v4 相同背景数据通过该接口送入正式 renderer 与编辑器/固定回放，保存一致的输入和物理面板矩形；N03/N04 在此入口完成后再集成。固定与 live 的单位验证用同等内容的专用背景，不把程序渐变说成固定图片。

### 4.6 新样式外形与阴影的明确约定

- 为避免影响旧图，新样式使用独立几何分支；旧 GPU 样式保留既有物理几何语义，旧 GDI+ 不改。新样式主题几何为 DIP，唯一转换点为 frame/layout builder，乘 `DeviceDpi/96 × UIScale` 一次；正式布局已经转换的物理 bounds 不再相乘。捕获坐标始终为全局物理坐标。
- 冻结新样式的同一物理几何快照：客户区、材质根矩形、内容矩形、圆角、Region 和外部阴影边界。新样式 Region 与 shader 使用该快照，不能分别读取未缩放的 rendering.cornerRadius 与另一套 layout.cornerRadius。
- 生产面板保持现有单一顶层窗口。外部投影优先使用系统已有窗口阴影能力；shader 负责玻璃内的边缘与接触层，不以扩大后的第二个硬轮廓画假外壳。不能在 AlphaMode.Ignore 的不透明交换链外随意加“透明 padding”，也不通过新置顶背景/双窗来造影。
- N03 需要交付真实窗口的阴影与 Region 对照：固定回放可完整显示参考阴影，真实窗口的外部投影由系统合成，其差异必须说明。系统不支持外投影时允许单外壳的无外影降级，并准确记录；不得因阴影被客户区裁切却宣称像素等同 v4。
- 几何夹具覆盖 96/144/168/192 DPI 与 UIScale=1/1.5/2，长短边、实际 Region 及 DPI 往返。旧分支不得顺手全局乘缩放系数；确有旧几何缺陷时单独立项说明其差异，不能与 live UV 修复混在一起。

### 4.7 颜色与透明度合同（N01 必交付）

- 先沿用既有 SDR 行为：背景/输出为 `B8G8R8A8_UNorm`，明确保持当前编码空间运算，不宣称是新的线性光/HDR 管线。固定纹理和 live 在相同格式上合成。
- D2D 前景为预乘 alpha；合成采用 `bg*(1-fg.a)+fg.rgb`，不得再次预乘。离屏/交换链输出 alpha=1，交换链 `AlphaMode.Ignore`；客户区外形由 Region 裁切。对半透明文字、轨道和颜色已知的前景保存计算对照。
- `fogStrength` 为模糊混合比例、`tintStrength` 为中性染色权重，与窗口透明度分开；v4 0.16/0.038 不得映射成 `Form.Opacity`。`Form.Opacity` 由窗口层应用一次，不在 shader 和画笔中重复乘。
- 生产与编辑器对相同输入使用相同材质颜色处理；编辑器宿主未应用整个窗体透明度时必须说明预览边界，不把宿主差异标为同一窗口 alpha 已验证。窗口透明度 1.0/0.96/0.7 的真实检查与材质雾量、染色检查分开记录。

## 7. 验收清单与失败规则

### 7.1 固定场景与视觉

- 与 v4 对齐的样板场景保持 1280×900、同一固定背景、同参数、固定时间，验证背景材质，不要求真实业务前景与演示文字逐像素一致。
- 对 v4 背景材质提取固定输入/几何参考，比较边缘、雾量与阴影；如改为共享材质，留存改前后对照与差异解释。
- 增加对比背景：浅色、深色、明暗交界、细线/棋盘格；检查边界采样连续、圆角无双轮廓、前景清晰且进度值准确。不要用只适合浅背景的一张图代表所有背景可用。
- 旧 GDI+ 全部基线主题同数据逐像素比对。旧 GPU 赛博和未受缺陷修复影响的固定玻璃保留参考图；live blur 修复的差异单独说明。

### 7.2 自动化与真实窗口

执行阶段允许为本计划的验证新增和运行针对性测试；计划与复审阶段不运行测试。沿用现有 `run-probes.ps1`、`run-gpu-contracts.ps1`、主工程/更新器测试及专用 GUI probes，检查实际项目/参数存在后再执行。

可新增一个仅负责枚举这些入口与聚合结果的非性能验收 manifest/runner。不得默认调用 `run-gpu-performance.ps1` 或 `run-stress.ps1`，不得把耗时性能组藏在通用 runner 内；逐组记录命令、退出码、运行时长和 FAIL/SKIP 原因。

现存通用入口不视为天然“非性能”：执行前逐个审计其内部模式与测试用例。特别是 `AppearanceM2Probe`、窗口/资源探针及 GPU 合同测试中的 CPU 配对、耗时预算、分配/增长斜率与帧率验收，需用明确过滤参数排除；没有过滤入口时先由 QA 增加组选择，默认行为兼容原调用。生命周期状态/资源归零/单 worker/单捕获仍运行，CPU/GPU 时长阈值及长时增长预算不运行。manifest 记录被用户延期的具体用例及原因，与功能 SKIP 分开，不能通过按整个类名筛选意外执行延期用例。

每个必需入口必须：检查 csproj 存在；使用冻结候选源码构建；校验构建退出码；核对产物哈希/时间/输入；启动自有子进程并设置外部功能时限与可取消退出；保留 stdout/stderr/诊断和状态；完成后确认无自有探针残留。缺项目/构建失败/没有新产物时禁止运行旧 EXE。超时、无断言/零用例、必要功能 SKIP、缺必需证据或版本不一致均阻断该组，不得因 exit0 单独判 PASS。硬件/环境条件不足需明确 BLOCKED，不能将其忽略在绿色汇总之外。

### 7.2.1 原计划 §10 的非性能承接 manifest（必交付）

N09/N12 必须逐条对照原计划 §10 建立机器可读清单，至少覆盖：旧主题全量固定 mock 像素基线；CPU/GPU/内存/NET/DISK/流量/历史/告警/缺失值的数据投影；1/4 GPU、横竖/双列/纯文本/全关闭布局；穿透/拖动/双击/右键/键盘；隐藏/最小化/尺寸/句柄/透明度/置顶；可用屏幕与 DPI；旧↔GPU↔旧与快速连续切换；配置只读/取消/保存/未知字段；编辑器恢复/另存/同源预览与零捕获；任务栏/tooltip/网页/热键/托盘/更新/自启/FPS 插件入口；截图/录屏共存；GPU 拒绝/设备丢失/超时/恢复失败回退；干净解压/缺资源/无 SDK/安全启动。

每项映射到实际存在的测试/探针/手工步骤、必需性、当前支持条件、负责人、最终候选哈希和具体结果；网络、更新、自启等不可对用户产生真实副作用的动作采用已存在的隔离/注入入口。无入口先实现最小可检查夹具，不以“有单测”笼统代替该功能。编译/自动夹具、真实 GPU、真实窗口、人工目视必须分列。项目“全回归通过”要求该清单所有必需项有有效结果。

功能生命周期最多使用必要的短循环（如 10 次换肤/显隐与句柄重建），检查归零/无重复 worker，不以此声明长时泄漏或性能通过。失败先定位并加最小回归，再重跑受影响组；不因工具失败反复重跑整套测试。

### 7.3 实机、权限与无法取得的环境

最低必要项：当前机器上的真实正式窗口、新主题/赛博/旧主题切换、设置和编辑器、捕获显隐与恢复、现有多屏往返、实际打包程序启动与回退。缺少这些结果不得声明本轮全部完成。

HDR、跨显卡、旋转屏、远程会话、其他 Windows 版本属于兼容边界，不为“全完成”而临时实现新平台能力；只能在确实不存在对应环境且文档明确限定支持范围时记为不支持/未验证，不伪造 PASS。不能用这一条跳过机器上已有的多屏与缩放验证。

需要 UAC、录屏工具或人工目视时，先把所有可独立事项和候选产物完成，给出具体程序、命令、隔离目录与单项操作，再请求必要交互。禁止为了测试修改 manifest 去掉管理员权限后声称正式包通过。等待人工步骤时继续完成不依赖它的工作。

### 7.4 新的非性能完成状态

任务结果使用：PASS / FAIL / BLOCKED-ENVIRONMENT / NOT-APPLICABLE（需写支持范围和原因）。必要项的 FAIL/BLOCKED 阻断“所有非性能完成”。

原 G4 标记为“用户要求延期，既有失败保留”；原 G5 不因本轮非性能完成而自动改为全量发布通过。可交付清晰标注性能待处理的本地候选 ZIP，不宣称最终全项发布认证。
