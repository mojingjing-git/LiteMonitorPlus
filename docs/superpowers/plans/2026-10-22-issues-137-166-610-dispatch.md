# #137 / #166 / #610 实施与派发总计划

日期：2026-10-22。目标：为三个上游需求形成可独立实施、复审和合并的任务。本轮只编写计划。

## 1. 结论与推荐顺序

| 顺序 | 需求 | 当前事实 | 实施重点 | 难度 |
|---|---|---|---|---|
| 1 | #137 内存已提交占用率 | 只有物理内存占用率及其容量换算 | 原生系统提交量快照、独立指标、正确显示提交上限 | 中 |
| 2 | #166 CPU 电压上面板/任务栏 | 已有 `CPU.Voltage`、配置项、传感器匹配、V 单位和语言标签 | 核实已有功能，补齐来源选择、VID 语义及缺失状态 | 低至中，受硬件支持限制 |
| 3 | #610 排除指定 IP 流量 | 网卡累计字节与 LHM 速率没有对端 IP；SMB 扣除是独立估算路径 | 先验证事件采集能力，再实现实时网速排除 | 高 |

推荐先交付 #137 和 #166；#610 的技术验证可独立推进。#610 通过采集能力和性能门槛后再接入正式产品。

## 2. 需求来源与已经固定的产品口径

- [#137 原始需求](https://github.com/Diorser/LiteMonitor/issues/137)：支持查看任务管理器“已提交”对应的占用情况，评论还要求直观看到当前量/上限。
- [#166 原始需求](https://github.com/Diorser/LiteMonitor/issues/166)：把 CPU 电压放到面板和任务栏，包括 i9-14900HX 用户的诉求。
- [#610 原始需求](https://github.com/Diorser/LiteMonitor/issues/610)：指定局域网设备 IP，剔除 UDP/RTP 音频串流造成的实时上传速度；现有 SMB 开关不能满足。

本计划采用以下默认方案，避免实施时自行改变指标含义：

1. **#137 新增独立“内存已提交”监控项。** 用户可选择它替代物理内存显示，也可同时显示；原 `MEM.Load` 保留物理内存含义和默认布局。
2. **#166 复用现有 `CPU.Voltage`。** 先证明原链路能显示，再修实际缺口。实测核心电压与请求电压 VID 必须区分。
3. **#610 第一版作用于 `NET.Up/NET.Down` 的实时网速。** 日累计、会话累计沿用原有统计口径，界面说明这一点；累计流量按 IP 排除列为后续独立任务，不能悄悄混入。此范围直接对应 issue 中“网速统计”的诉求。
4. 三项均默认保持升级前行为：新内存项隐藏、CPU 电压保留原显示选择、IP 排除关闭且列表为空。

## 6. 统一交付与验证纪律

每个实施任务必须交付：

1. 提交 SHA、变更文件、设置默认值、兼容性及回滚方式。
2. 核心行为测试及失败路径测试；不是只检查源码含某个单词。
3. 对旧实现/移除核心修复的变异，证明新增测试能变红；正常路径提供阳性对照。
4. 从独立干净副本执行 `dotnet build tests/LiteMonitor.Tests/LiteMonitor.Tests.csproj -c Release --no-incremental`，成功后执行 `dotnet test ... -c Release --no-build`。按当前项目记录完整总数、失败数、跳过数和退出码。
5. 记录被测提交、源文件哈希、产物 SHA-256；文件替换或变异后重新强制构建，防止陈旧 DLL。
6. 有同步交错的测试用事件/屏障控制；不用 Thread.Sleep 制造竞态。
7. 真实设备/权限不足写“未验证”，不能用假设备通过代替实机结论。

三项都必须保留本批已有的采集约束：普通硬件由共享协调器限频；UI/Web 不旁路采集；取值按采集代次复用；配置切换使必要快照失效；缺失数据不是 0；Stop 可恢复、Dispose 不可复活；旧回调不能写入新代次。
