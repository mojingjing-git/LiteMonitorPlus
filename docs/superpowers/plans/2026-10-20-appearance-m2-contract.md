## 0. 为什么必须先冻结

复核报告 §4.3 明确要求：**先由集成者冻结捕获请求、帧来源、代次、所有权和测量字段，再派发 A15**。
原因：这几个字段同时被捕获后端、图像处理、后台服务、主面板接线、探针五方读写。
先写代码再定协议，结果是每方各自发明一套语义，A16 接线时必然返工，
而返工点在**位图所有权**上——那是唯一会造成不可逆泄漏（句柄/位图泄漏、跨线程释放崩溃）的地方。

本文件只冻结**接口语义**，不规定实现细节。实现可以变，语义不能变。

## 1. 术语与角色

| 角色 | 是什么 | 不是什么 |
|---|---|---|
| **捕获请求**（CaptureRequest） | 一份**不可变**的请求快照：客户区物理矩形、DPI/用户缩放、主题代次、窗口句柄代次、模糊半径、帧率 | 不是任务队列，不是可变对象 |
| **帧提供者**（`IBackdropFrameSource`） | 把"当前这一帧的底图"交给背景层渲染器的**只读**接口 | 不启动捕获、不创建线程、不持有 UI 对象 |
| **捕获后端**（A15 实现） | 真正做屏幕捕获的组件 | 不直接被 UI 绘制；不直接释放 UI 的位图 |
| **后台服务**（A15 实现） | 单后台任务，把"请求"变成"发布候选帧" | 不释放 UI 正在使用的位图 |
| **UI 侧 active 帧** | 当前被绘制路径借用的那一帧 | 借用引用，不得被后台释放 |

## 2. 帧来源（Source）—— 已冻结两层保险

背景层的 `BackdropStatus.Source` 有且仅有三个值，**语义如下，不得新增第四个**：

| 值 | 含义 | 判定依据 |
|---|---|---|
| `LiveFrame` | **真实捕获**帧 | `options.PreviewSource == null` **且** `IBackdropFrameSource.IsPreview == false` |
| `PreviewFrame` | 预览固定图 | `options.PreviewSource != null` **或** `IBackdropFrameSource.IsPreview == true` |
| `Gradient` / `Legacy` / `None` | 非帧底图（渐变 / 旧路径 / 无底图） | 降级链结果 |

### 2.1 两层保险（复核 N2 的根治要求）

**第一层 · 结构保险（首选）**：预览路径**根本不注册帧后端**，
固定样例图通过 `ThemeAppearanceOptions.PreviewSource` 进入快照。
⇒ `options.PreviewSource != null` ⇒ 背景层**不访问后端**（后端 `TryGetFrame` 调用次数 = 0），
   来源报 `PreviewFrame`。
⇒ 这是**结构性保证**，不依赖任何人记得填对字段。

**第二层 · 元数据保险（兜底）**：`IBackdropFrameSource.IsPreview` 由**帧提供者自己声明**。
⇒ 真实捕获后端必须返回 `false`；
   固定图提供者（编辑器预览适配器、探针假后端）必须返回 `true`。
⇒ 即使有人误把固定图包成帧后端注入，**诊断也不会把它记成实时帧**。

### 2.2 对 A15 的强制要求

1. **A15 的真实捕获后端必须实现 `IsPreview => false`。** 这是硬性契约，代码评审逐条核对。
2. A15 **不得**为预览提供帧后端。预览只走第一层。
3. **任何**把固定/合成图包装成 `IBackdropFrameSource` 的代码（探针、测试、未来适配器）
   必须返回 `IsPreview => true`。
4. `ThemePreviewControl`（编辑器）**绝不**启动捕获服务：它只持有固定样例图。
   编辑器预览与主面板的玻璃效果**互不影响**。

### 2.3 不得引入的捷径

- ❌ 把 `Source` 直接写死成 `LiveFrame` 或按"有没有后端"猜。
- ❌ 在编辑器里注册真实捕获后端（会让预览变成"偷偷抓桌面"）。
- ❌ 用"帧非空"当作"这是实时帧"的判据。

## 3. 代次（Generation）—— 已冻结

| 代次 | 含义 | 递增时机 | 作用 |
|---|---|---|---|
| **主题代次** `themeGeneration` | 主题/外观快照的版本 | 换肤时自增（`AppearanceRuntime.OnThemeChanged`） | 装饰层、背景层纹理缓存失效；**已有实现** |
| **窗口句柄代次** `handleGeneration` | HWND 的版本 | 句柄被销毁/重建时自增 | 捕获结果归属校验：旧句柄的结果必须丢弃 |
| **尺寸代次** `sizeGeneration` | 客户区几何的版本 | 客户区尺寸变化时自增 | 旧尺寸的帧必须丢弃 |

### 3.1 规则

1. **代次只增不减**，由**唯一 owner**（主面板接线方）维护。
2. 捕获请求**携带**它发起时的三个代次。
3. 后台/后端返回帧时**回带**它处理请求时的代次。
4. **UI 侧比对**：当前代次 ≠ 帧代次 ⇒ **丢弃该帧**（不绘制、不释放到错误的地方）。
5. 主题代次变化 ⇒ 装饰/背景层缓存失效（已有实现，勿改）。

### 3.2 为什么要有句柄代次

句柄重建（窗口跨屏移动、句柄被系统回收重建）后，**旧 HWND 的捕获结果毫无意义**，
且 `SetWindowDisplayAffinity` 施加在旧句柄上，新句柄**不继承排除属性**
⇒ 会出现"面板被自己的捕获捕获到"的自反馈（A06 §4 记录的自反馈现象）。
代次比对是**唯一的**防自反馈兜底（排除属性本身也可能因外部原因被重置）。

## 4. 所有权（Ownership）—— 已冻结，最严格的一条

### 4.1 位图所有权表

| 对象 | 谁创建 | 谁释放 | 规则 |
|---|---|---|---|
| **pending 候选帧** | 后台服务 | 后台服务（若未被接管）**或** UI（接管后） | 同一时刻**最多一份** pending |
| **active 帧**（正在被绘制） | 后台服务创建 → UI 接管 | **UI**（接管时接管所有权） | 绘制期间**任何人不得释放** |
| **被丢弃的过期帧** | 后台服务 | **后台服务**（发布方） | 代次不匹配的帧由发布方回收，**不交给 UI** |
| **options.BackgroundFrame / PreviewSource** | 外部 | 外部 | **纯借用**；options 与渲染器都不释放 |
| **纹理/噪点缓存里的位图** | 装饰/背景层缓存 | 缓存 | 见 §4.3 |

### 4.2 核心规则（不可协商）

1. **后台只发布 pending，绝不释放 UI 正在绘制的 Bitmap。**
2. **UI 接管 active**：只有在**没有任何 Paint 正在使用旧帧**时才替换并释放旧帧。
3. **后台不得释放已被 UI 接管的帧。** 接管是一次性的所有权转移，转移后后台对该帧**无任何权利**。
4. **代次不匹配的帧由后台自己回收**，不得丢给 UI（UI 也不得接收）。
5. **pending 最多一份**：新帧产生时，若旧 pending 尚未被接管，后台**先释放旧的**再发布新的。
   不允许堆积（否则内存预算随帧率线性增长）。
6. **失败路径必须释放**：捕获失败、滤波失败、取消、句柄失效、超时——
   都要释放"已创建但未发布"的中间位图，不得泄漏。

### 4.3 缓存资源所有权（已有实现，A14 加固后）

- 装饰层缓存（`DecorResourceCache`）：缓存**同时拥有**源位图与画刷，淘汰时两者一起释放。
- **入表成功之前**，待接管的位图/画刷由当次调用用 `try/finally` 兜底释放；
  **只有入表成功才提交所有权与字节计数**（A14 加固项）。
- 记账（`_totalBytes` / 创建数）与释放指向**同一份图像**。

### 4.4 借用引用清单（渲染器绝不释放）

- `ThemeAppearanceOptions.BackgroundFrame`
- `ThemeAppearanceOptions.PreviewSource`
- `IBackdropFrameSource.TryGetFrame` 返回的帧

## 5. 取消与生命周期 —— 已冻结

### 5.1 何时不捕获

| 条件 | 行为 |
|---|---|
| 主题不是 glass（gradient/solid） | **不启动服务** |
| 玻璃开关未开启 | **不启动服务**（默认关闭） |
| 窗口隐藏 / 最小化 | **暂停捕获** |
| 窗口关闭 / 应用退出 | **停止服务并释放全部原生资源** |
| 句柄失效 | 停止该句柄的捕获，恢复显示亲和性 |

恢复可见时**合并为一帧**（不补历史帧、不追帧）。

### 5.2 取消协议

1. **单一取消令牌**：服务生命周期一个 CTS，退出/模式切换/关闭时取消。
2. **取消必须可等待但有上限**：不阻塞 UI 无限等后台退出。
3. **取消/失败后必须恢复显示亲和性**：`SetWindowDisplayAffinity` 的排除属性要还原，
   否则窗口在录屏里永久消失。
4. **失败后受控重试**：有退避，**不在每次 Paint 里无限重试**。
5. **`Paint` 与 `TryGetFrame` 只读当前帧，绝不启动抓屏。** 这是硬红线：
   绘制路径里出现捕获调用即为设计错误。

### 5.3 显示亲和性的作用域

A06 实测：`WDA_EXCLUDEFROMCAPTURE` 是**窗口级**的，
排除的是**整个窗口**，不是窗口内某个矩形。
⇒ 若产品将来需要"只排除面板背景、保留文字"，当前 API 做不到，必须另找方案。
⇒ A15 **不得**自行扩大排除范围到其它窗口。

## 6. 测量字段 —— 已冻结（含口径区分）

### 6.1 两种口径，不得混用

| 口径 | 测什么 | 用什么测 | 判据用途 |
|---|---|---|---|
| **CPU 时间** | 处理器时间（不含等待/抢占） | `Process.TotalProcessorTime` 差值 ÷ 次数 | **CPU 预算**（≤40ms/秒） |
| **经过时间** | 墙钟（等待、抢占都算） | `Stopwatch` | **延迟判据**（p95 ≤30ms） |

**Windows 的进程 CPU 时钟粒度约 15.6ms**，单次操作无法直接测。
⇒ CPU 口径必须**批量执行**（建议 ≥2000 次/批）后取每操作均值；
   必须**同进程同刻**做 old/new 配对；必须**交替执行顺序**；必须**≥3 轮**并逐轮记录；
   差值落在噪声内时**如实报"不可判定"，不得报 0**。

### 6.2 M2 必须分别记录的分段耗时

| 分段 | 说明 |
|---|---|
| `captureMs` | 捕获（含后端自身开销） |
| `filterMs` | 降采样 + 物理模糊半径滤波 |
| `publishMs` | 发布候选帧（含代次校验） |
| `waitUiMs` | **等待 UI 接管**的时长（后台阻塞的根源） |
| `excludeWindowMs` | **瞬时排除窗口**的时长（排除属性生效期间无法捕获） |
| `cpuMsTotal` | 上述合计的**处理器时间** |
| `elapsedMsP95` | 单次端到端**经过时间**的 p95 |

`waitUiMs` 与 `excludeWindowMs` 必须**并列记录**：
它们是"后台占用"里最容易被漏掉、也最容易失控的两段。

### 6.3 预算

| 判据 | 值 | 口径 |
|---|---|---|
| 后台 CPU | ≤ **40 ms/秒** | CPU 时间 |
| 单次处理延迟 p95 | ≤ **30 ms** | 经过时间 |
| 默认帧率 / 上限 | 2 fps / 6 fps | v4 §7.4 |
| 缓冲预算（采集像素 + 临时 + pending + active） | 按 v4 执行 | A06 的 `captureScale=0.25` 是候选起点，须按实际最大面板尺寸重测 |

### 6.4 不得再犯的口径错误

**A14 的教训**：`MeasurePaired` 用 `Stopwatch` 得到的是**经过时间**，
但验收文档把它写成"额外 CPU"，并据此推算"整机 CPU 增加 0.85 个百分点"。
⇒ A14 验收文档 §3.1/§3.4/§4.2/§6.4/§6.5 中所有"额外 CPU"表述
   **已在本轮改为"额外经过时间"**，整机推算已明确标注口径与假设。
⇒ **M2 的任何报告不得重犯**：CPU 预算只认 CPU 口径，延迟只认经过时间口径。

## 7. 降级链与状态可见 —— 已冻结

1. 保留 `glass → gradient → solid` 的**实际**生效状态与**原因码**
   （`BackdropDegradeReason`：`BackendMissing` / `BackendNotReady` / `BackendFrameInvalid` /
   `GradientUnavailable` / `InvalidBounds`）。
2. **降级不静默**：每次降级都要有可读原因，能进日志/UI。
3. 原因码**不得**用主窗口语境去描述预览场景（反之亦然）：
   编辑器预览没有样例图 ⇒ 报"预览没有固定样例图"，
   而**不是**"未注册实时背景后端"。

## 8. 默认关闭与首次提示 —— 已冻结

1. **实时玻璃默认关闭。**
2. **显式开启 + 首次提示**在 **A16 首次接入真实捕获时同时提供**（不能拖到 A17）。
3. 提示必须如实表述副作用：**捕获瞬间面板可能从录屏/截图中短暂消失或闪动**。
4. 不能据 A06 的先前观察占空比保证所有录屏软件都无感。
5. 编辑器固定预览**不启动服务**，也不弹该提示。

## 9. A15 的验收门槛（派发前自检）

派发 A15 前，集成者需确认下列每一条都能被自动化检查：

| # | 门槛 | 检查方式 |
|---|---|---|
| 1 | 捕获后端 `IsPreview => false` | 源码 + 探针断言 |
| 2 | 预览路径后端调用次数 = 0 | 探针（假后端计数） |
| 3 | `Source` 三值语义正确 | 探针（真实/预览/降级三种情形） |
| 4 | 代次不匹配的帧被丢弃且被回收 | 探针（造过期帧，断言不绘制 + 计数归零） |
| 5 | pending 最多一份 | 探针（连续发布，断言 pending 计数 ≤1） |
| 6 | 取消后恢复显示亲和性 | 探针 + 源码 |
| 7 | 绘制路径无捕获调用 | 源码扫描（`BitBlt`/`CopyFromScreen`/`DXGI` 等零命中） |
| 8 | CPU 与经过时间分别计量 | 探针输出含两个口径的字段 |
| 9 | 缓冲预算有界 | 探针（像素/字节计数） |
| 10 | 无新增 NuGet 依赖 | `*.csproj` diff |
