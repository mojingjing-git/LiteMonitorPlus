## 3. P1 必改项（Must-Fix Items）

#### [P1-1] 表 7.4 T01 与表 7.3 D01 残留对 R1 的无意义依赖，与 §0 关键路径及 §8.1 波次表冲突
- **位置**：§7.4 表 7.4 第 272 行（T01）、§7.3 表 7.3 第 261 行（D01）、§16.1 Mermaid 图第 513 行。
- **证据**：
  1. §0 关键路径（第 24–29 行）中，第二分支 `D01–D04 + T01–T03` 直接从 `C1/C2/C3 合同冻结` 引出，并不依赖 R1。
  2. §8.1 表 8.1（第 323 行）中，波次 W1 明确允许 `R1、R4、D01–D02、T01–T02、S01–S02、P01–P02` 并行推进（硬前置仅 G0）。
  3. 但在 §7.4 表 7.4 第 272 行，T01（快照消费/身份/质量适配）的依赖列仍写为：`C3、R1`。
  4. T01 是对 `HardwareSnapshot`、`StableDeviceId`、批次去重及质量适配的数据层实现，与 R1（GPU代次同步、DPI布局、最小化停帧）在代码和架构上**没有任何调用关系**。若严格按照 WBS 依赖执行，B 无法在 W1 启动 T01，必须等待 A 花费 5–7 人日完成 R1，直接破坏了 §8.1 并行安排。
  5. 同样，表 7.3 第 261 行 D01 写为 `依赖：C1、R1`；§16.1 Mermaid 图第 513 行写为 `R1 --> R3`（而在表 7.2 中 R3 仅依赖 `INF-02/INF-06`）。
- **影响**：依赖列残留旧文字，导致 WBS 与关键路径图、波次表逻辑冲突，可能被自动化看板或严格的项目经理作为前置阻断开发。
- **具体修法**：
  - 将表 7.4 T01 依赖从 `C3、R1` 修正为 `C3`。
  - 将表 7.3 D01 依赖从 `C1、R1` 修正为 `C1`（或说明仅渲染 Provider 消费 R1，其余 Provider 立即开工）。
  - 删除 §16.1 Mermaid 图第 513 行的 `R1 --> R3`。
