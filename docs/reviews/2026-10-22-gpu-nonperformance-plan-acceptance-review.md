## 初审记录（历史，以下三项均已关闭）

初审结论为 NEEDS-REVISION，版本 SHA256：`08E41CBF9563C8449B34E2F2F064AAC2A73BFC016A971DAC45B58BFC87C90498`。本节位置与行号保留指向初审版本，供追溯问题依据；不再作为未完成修订清单。

### A1 · P1：明确排除通用探针内已经存在的性能用例

位置：计划 §7.2，第 123–127 行。

计划同时要求“不进行 CPU/GPU 配对、帧率预算验收”和“沿用 run-probes.ps1”，但现有默认调用链存在直接冲突：

- `scripts/run-probes.ps1:96` 收录 `AppearanceDecorRendererProbe`。
- 该探针 `Program.cs` 无功能子集选择，直接调用 `runner.RunAll()`。
- `tests/AppearanceDecorRendererProbe/DecorRendererProbeRunner.cs:48` 无条件调用 `RunFrameCost()`；第 841 行起进行多档预热、旧/新路径配对计时、三轮测量及预算断言，第 970 行可因性能预算失败而令整个探针失败。

因此仅禁止调用 `run-gpu-performance.ps1`、`run-stress.ps1`，或禁止“新增隐藏性能组”，不能落实本轮性能暂停。

**最小修订：**要求 QA 在执行前确认递归到具体用例的非性能允许清单；上述探针只选择功能用例，或提供明确跳过成本测量的入口。性能用例记为本轮延期，不执行后再忽略其失败。保留旧主题像素、裁剪、缓存有界性和资源释放等正确性断言，无需修改旧业务或恢复性能排查。

### A2 · P2：将原计划 §10 的非性能承接清单设为必交付项

位置：计划 N04–N09、§7.2，第 86–91、125 行。

任务类别基本齐全，但“入口可用”和可选的聚合 manifest 尚不能证明原 §10 全部非性能断言已经承接。例如以下原有要求未在本计划完成条件中明确落点：

- 采样与业务：渲染不额外调用 `Update()`、更新频率和业务结果不变、缺失传感器；这些是功能断言，不是重启性能测量。
- 布局与配置：排序/重命名/显隐、全指标关闭的空态、横屏单行；损坏字段和重启后的状态、编辑器 GPU 不可用。
- 窗口与故障：最小化/淡入、帧超时、锁屏及休眠恢复；不能将它们全部等同于 AccessLost 或显隐。
- 外围与共存：任务栏 tooltip、浅深色/字体缓存/多屏及 Explorer 重建后的恢复；系统截图、至少一种录屏、两个面板/预览窗口的共存。

R20 的旧矩阵仅记录 168 DPI 下的少量横竖及 legacy-route 结果，仍明确列多屏和 DPI 实机迁移未验证；不能用它或总测试数补齐这些断言。

**最小修订：**把验收 manifest/清单改为必须冻结，逐行映射原 §10 的非性能要求到已有证据、定向用例或必要人工步骤，注明 N 任务、验证层级、必要性、断言和结果。可以引用现成用例，不要求重写旧功能或新增一整套测试。锁屏、休眠、Explorer 重启、屏幕拔插等会影响桌面的动作不得由 runner 自动执行；需要实机动作时按 §7.3 交给用户进行单项操作，未完成保留阻塞。不存在的 HDR/旋转/跨显卡/其他 Windows 环境可按已限定支持范围记为未验证；当前已有多屏不能这样豁免。

### A3 · P2：补上现有 runner 的失败、缺项和超时判定

位置：计划 §7.2、§7.4，第 123–127、139 行。

现有脚本并不天然满足统一验收需要：

- `run-probes.ps1:140` 遇到缺失项目直接 `continue`；若残留 EXE 存在，后续仍可能运行旧产物。
- 第 99 行把实机探针固定指向 `bin/Release`，与可选择的 `Configuration` 不一致。
- 第 158、215、233 行允许 SKIP 与最终退出码 0 共存；普通入口也不包含更新器测试，不能把入口成功等同于必要组齐全。
- 第 122–124 行串行 `ReadToEnd()` 后无期限等待退出；`run-gpu-contracts.ps1:69` 的 live `dotnet run` 也没有外部 watchdog。现有取消能力不能覆盖 UI 或子进程卡住的情况。

**最小修订：**在执行清单中强制由 QA 修正或包装这些行为：必要项目缺失/构建失败立即阻断且不运行旧 EXE；核对构建配置和实际产物身份；解析各组结果，必要的 SKIP/未验证转为阻塞，不能只汇总退出码。为真实窗口/捕获子进程落实计划已有的外部时限、取消和退出宽限，超时仅清理本次创建的进程树并保留证据。重试限于定位后的受影响组，不因环境/UAC/工具失败反复跑整套。无需重写三个公共脚本，可靠包装同样可以满足要求。
