## 1. 最高优先级：你的 fork 必然继承的 bug

### 🔴 PR #586 —— Intel 核显 / AMD APU 的 GPU 占用率永远为 0 且无法自愈
`MoonAsked` ｜ OPEN ｜ +31/-5 ｜ 2 文件
关联 issue：#569、#521、#463、#434、#450

**根因（三层，环环相扣）**：

1. **传感器懒激活** —— LibreHardwareMonitor 中，Intel 核显（`IntelIntegratedGpu`）的负载（`D3D 3D`）与显存（`D3D Shared Memory *`）传感器，以及 AMD 的负载传感器（`AmdGpu._coreLoad`），在硬件对象**构造时仅创建实例**，首次 `hw.Update()` 之后才注册进 `Sensors` 集合。而 NVIDIA / Intel Arc 独显的构造函数末尾自调 `Update()`，所以传感器开箱即就绪 —— **这正是独显正常、核显/AMD APU 失效的原因**。
2. **建表早于更新** —— `SensorMap.Rebuild()` 先于任何 GPU Update 执行，建表瞬间核显/AMD 的 `Sensors` 里没有可映射的负载传感器，`GPU.Load` 等键直接缺失。
3. **缓存无法自愈** —— 取值走 `PreCacheAllSensors()` 生成的静态缓存，只在配置变更/重载时刷新；即使 10 分钟兜底重建（`EnsureFresh`）把键补进映射表，**取值缓存里依然没有** —— 这就是"永远不出现"的原因。

**修复**：Rebuild 前对"将参与映射但负载/显存传感器尚未激活"的显卡补一次 `Update()`；`EnsureFresh` 返回是否发生重建；兜底重建后同步调用 `PreCacheAllSensors` 刷新缓存。实测预热 Update 约 7ms，仅在启动/重载/切换显卡/10 分钟兜底时触发，热路径零改动。

**→ 对你 fork 的意义（已实测确认）**：
- 你的 `src/System/HardwareServices/SensorMap.cs:171` 有一行 **`//hw.Update();` 被注释掉**，且全仓**无任何 GPU 预热调用**。
- 你的 fork 正在做多卡改造（`SelectMonitoredGpus` / `FindGpuIndex` / `GpuRegistry` / `MonitoredGpuCount` 均已落地），**必然继承这个 bug**：Intel 核显或 AMD APU 机器上，多卡模式的 `GPU.0.Load` 会缺失且无法自愈。
- **建议优先级：P0**。这是你 fork 里最实在的一个"上游未修、你可以领先"的 bug。

### 🟡 PR #495 —— 副屏任务栏重启后不显示 + 高度异常
`Hsyoungtick` ｜ OPEN ｜ +95/-34 ｜ 3 文件

根因二连：
1. **`FindHandles` fallback 到主屏** —— 启动时副屏任务栏（`Shell_SecondaryTrayWnd`）可能尚未就绪，原代码 fallback 到主屏 `Shell_TrayWnd`，且 Tick 重试逻辑检测不到这个错误 → 永远停在主屏。
2. **DPI 缩放导致坐标空间不一致** —— `Screen.Bounds` 返回物理像素，`Screen.WorkingArea` 返回逻辑像素，两者相减得到错误高度（如 424px 而非 40px）→ 窗口被拉伸但内容不可见。

**→ 你的 fork 需自查**：`src/UI/Helpers/TaskbarWinHelper.cs:247-248` 同时使用 `screen.WorkingArea` 与 `screen.Bounds`，`:268-276` 已有"标准高度强制修正"（`48.0 * dpi / 96.0`），看起来已做过类似处理，但**两套坐标系是否混算**需要实测复核（Win10 22H2 + 主屏 100% / 副屏 150% 是复现条件）。
