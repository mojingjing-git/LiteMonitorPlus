## 1. 用户目标

用户打开诊断中心，可以回答“哪个模块有问题、数据上次何时有效、现在实际使用什么路线、可以采取什么动作”，并导出一份自己能先查看的本地脱敏诊断包。

首版复用 WinForms、设置配色与 Windows 原生标题栏。界面采用清晰状态卡和紧凑列表，普通说明在前，错误码、修订号和技术详情放在可展开区域。

## 2. 当前基础与接入点

| 已有能力 | 复用方式 |

## 3. 首版范围与用户流程

四个区域即可完成首版，不新增复杂仪表盘编辑器。

| 区域 | 首版内容 | 主要交互 |
|---|---|---|
| 总览 | 采集、显示、任务栏、Web、插件、配置应用的状态和最近一次变化 | 展开详情、前往相应设置 |
| 数据与设备 | 当前目录版本、设备化名、样本状态、上次有效时间、缺失原因 | 过滤异常项、查看来源；不逐秒重建整棵传感器树 |
| 事件 | GPU 回退、Host 重连、应用部分失败、插件连续失败等结构化时间线 | 按模块/严重程度过滤，复制脱敏详情 |
| 导出 | 文件清单、字段范围、大小估计及本地脱敏预览 | 选择保存路径、生成 ZIP、取消生成 |

入口放在托盘菜单和设置中的“诊断”。同一进程复用一个诊断窗口，重复点击激活已有窗口。关闭窗口只释放页面订阅，不停止采集或清空其他消费者。

“重试”仅连接已有受控命令，例如重试失败应用、显式硬件重扫或用户主动 GPU 重试；每个动作显示执行中/完成/失败。打开页面、展开详情和导出均不隐式执行恢复动作。

## 4. 数据与事件合同

拟新增的最小模型包括 `DiagnosticSnapshot`、`DiagnosticEvent`、模块只读 Provider 和有界 EventStore；名称实施时与现有类型核对，不新增独立采集框架。

### 状态快照

- 含采集时刻、模块来源、状态、原因码、当前操作、期望/实际修订及数据年龄；没有取得事实时用 Unknown/NotSupported。
- 观察“操作没有进展”时同时使用 `ProgressSeq`、样本时间及模块状态。不能仅凭 UI 几秒没变就宣称硬件死锁。
- 每模块允许短暂不同步，保留各自采集时间，界面不声称是跨模块原子快照。
- 只读 Provider 不拿 LHM 对象锁、不等待硬件命令、不扫描磁盘和网络。耗时查询后台化并有截止时间；单模块失败不会使整个中心空白。

### 事件

- 字段包含单调序号、UTC 显示时间、模块、严重程度、稳定原因码、操作标识、可公开的结构化上下文。
- 同进程排序使用序号与单调时间；Host 事件保留会话身份和接收顺序，不直接比较两个进程自定义的相对时间原点。
- 首版只记录状态迁移与必要故障摘要，不记录每一帧、每个传感器值和每次正常轮询。
- 上限 1024 条且序列化上下文总量不超过 2 MiB，单条上下文不超过 2 KiB。达到上限淘汰最旧记录，并保留丢弃数；相同故障限频合并且带次数，不无限输出。
- 默认进程内保留，不每条写盘。未来告警、场景、省电决策接同一出口；关闭诊断窗口不清空应用事件。

## 5. 诊断包与脱敏

采用“明确列出的结构化字段”生成，不直接打包整个配置目录或原始错误日志目录。

| 默认包含 | 默认排除 |
|---|---|
| 应用/依赖版本、运行模式、协议版本、包内文件摘要 | 口令、令牌、Cookie、授权头、DPAPI 密文 |
| 当前模块状态、样本质量统计、渲染原因码 | 完整 Settings、插件输入、完整请求/响应和 Web 会话 |
| 有界结构化事件、采样/IPC/渲染计数 | 原始设备序列号、磁盘路径、用户名、内外网 IP 和带查询参数 URL |
| 设置字段的允许列表投影、操作结果 | 桌面截图、未明确选择的主题资源、任意系统日志 |

设备身份在单个包内使用稳定化名以便关联；每次导出使用新的随机映射，不携带还原表。错误消息先结构化和脱敏，不能因为来自 Exception 就直接加入包。

流程为“生成允许列表快照 → 后台写临时包 → 展示同一份待导出内容 → 用户保存”。预览与最终文件使用相同模型和过滤器，避免预览安全而 ZIP 多出原始内容。大小上限建议 10 MiB，超出时有明确截断清单；取消和失败删除本次临时文件，不留下半成品覆盖旧文件。

首版不上传、不提供网络发送按钮。敏感模式或原始日志导出不作为首版功能。

## 6. 任务拆分与所有权

| 编号 | 任务 | 交付与完成条件 |
|---|---|---|
| D01 | 模块事实适配 | 采集、渲染、配置结果、IPC、Web、插件各有 Provider；无法提供的字段明确缺失 |
| D02 | 有界事件收集器 | 注入事件出口；容量、合并、淘汰和关闭语义有测试 |
| D03 | 诊断窗口 | 实际菜单入口、异常过滤、详情与导航，浅/深色及键盘可用 |
| D04 | 导出服务 | 允许列表、同源预览、ZIP 清单/摘要、取消和原子完成 |
| D05 | 恢复动作接线 | 只复用受控命令，显示真实结果；重复点击合并或禁用 |
| D06 | 联调与基线 | 真实故障场景、资源测试、用户操作说明和证据 |

应用级所有者持有 EventStore、Provider 聚合与导出服务；窗口持有展示订阅。Provider 不引用窗体，后台完成不能更新已释放控件。优先通过现有组装根手工注入，未来 E04 迁移只移动所有权，不再替换合同。

## 7. 验收与性能预算

- 注入硬件初始化中、缺失/过期样本、GPU 首帧失败、Host 重连、Web 端口占用、插件失败和配置部分成功，页面说明与真实状态逐项一致。
- 打开/刷新/关闭诊断中心前后，实际采样、显式重扫和设备打开计数不因“查看”额外增长；不加载第二个采集器。
- 用虚构秘密、路径、IP、异常消息和插件输出做泄漏测试；预览、解压后的每个文件及文件名都检查。不能只扫描 ZIP 压缩字节。
- 事件超过容量、导出超过大小、磁盘失败、窗口关闭/导出取消时结果明确且无残留订阅。
- 页面可见时状态最多 1 Hz 刷新，隐藏后停止页面刷新；事件仅按迁移记录。初次开窗先显示缓存状态，慢模块后台补齐。
- 1024 条事件滚动、开关窗口 50 次，记录 UI 响应、句柄/GDI/USER 和稳态占用；功能预算为事件内容有界、无逐次增长。具体 CPU/内存数字经同机基线后填写，不预填节省比例。
- 真 GPU、Host、Web 路线分别复验；未启用或硬件不可得项单列，不以静态状态模型测试代替实机。

## 8. 发布边界

先交付 D01–D04 的只读中心与本地导出，再在 D05 接入已具备真实结果的动作。原设置中的诊断入口保留定位能力，但共用事实来源。帮助文案区分“已发现原因”“建议排查”“尚不支持诊断”，不从错误码推断未经验证的根因。

完成后为趋势告警、场景切换和低功耗提供统一事件与状态入口；这些功能各自的业务逻辑不放进诊断中心。
