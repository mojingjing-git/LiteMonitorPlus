## 2. R0：CI 与可复现基线

### F01 / P1：门禁参数不再依赖易错续行

落点：[ci.yml](../../.github/workflows/ci.yml)。

1. 将门禁 2 的构建参数改成 PowerShell 参数数组，或补齐现有续行；优先数组，避免参数增删再次拆成独立命令。
2. 保留 `%3B` 的 MSBuild 参数语义、原警告豁免名单和真实退出码判断；NuGetAudit 的环境处理不扩大成关闭全部警告。
3. 验证实际提交的 `run` 内容。若提取为 `.ps1`，CI 与本地直接调用同一个文件；不能另写一条正确命令替仓库脚本证明通过。
4. 用 PowerShell 解析与无构建副作用的命令替身检查参数边界，再执行真实 Release 门禁。

**通过条件**：脚本不产生 `-p:` 独立命令；构建错误能传出非零退出码；生产四工程零警告门禁与解决方案既有债务规则保持原语义。

## 3. R1：GPU 会话与布局生命周期

主要落点：[GpuThemePreviewControl](../../src/ThemeEditor/GpuThemePreviewControl.cs)、[ThemePreviewControl](../../src/ThemeEditor/ThemePreviewControl.cs)、[GpuSceneRenderer](../../src/Rendering/Presentation/GpuSceneRenderer.cs)、[FrameScheduling](../../src/Rendering/Gpu/Effects/FrameScheduling.cs)。

### F11 / P1：热更新提交同一组代次

1. 明确三种结果：更新请求已接受、配置已提交、目标修订已有成功帧。`UpdateTheme=true` 最多代表前两者，界面“预览已就绪”必须有目标修订的成功帧证据。
2. 增加或扩展渲染器的显式会话更新入口，使预览、场景和渲染器一起接受同一组 `RenderGenerations`；同尺寸更新也要执行。不要依赖 `Resize` 的尺寸变化副作用同步代次。
3. 提交前完成主题验证及派生配置构建。验证失败不污染上一成功会话；GPU 提交途中失败则进入明确失败/回退状态，不声称已原子回滚。
4. 区分资源创建时的归属代次与活动场景代次。设备/窗口/尺寸身份不匹配仍应拒绝；已有资源不能因主题代次增加而被错误归为另一设备所有。
5. 同材质与尺寸的普通调参复用设备。材质/设备重建走现有受控边界，记录原因，不用无条件重建掩盖失败。
6. 提供窄的只读诊断：请求修订、已呈现修订、活动代次、呈现帧数、实际设备创建数和失败码；计数取实际创建点。

**回归**：真实 GPU 启动后原样刷新；连续修改 30 次；主效果→兼容→主效果；拒绝非法参数后恢复合法参数；同尺寸与变尺寸更新。每次等待目标修订至少一帧成功呈现，确认后续帧仍增长、无代次错误，同材质调参设备创建数不增加。

### F08 / P2：首次创建和热更新统一 DPI 口径

1. 每个请求构建一份按当前 DPI 生成的预览快照，首次和热更新均使用它；原始文档保持逻辑尺寸。
2. 预览的布局、字体度量、材质 `dpi/userScale` 和场景边界从同一请求取得，避免 `_rawTheme` 与缩放副本混用；运行期字体借用与释放合同保持不变。
3. DPI 变化触发重新布局、场景提交及目标帧确认。重复处理同一 DPI 幂等，不重复缩放。

**回归**：96/120/144/168/192 DPI 的确定性几何测试；真实 175% 下 70 行高原样刷新仍为 70，反复刷新不漂移。混合 DPI 跨屏有条件实测；模拟 DPI 不记为真实跨屏通过。

### F07 / P2：最小化、隐藏与恢复独立处理

1. 呈现资格包含自身/祖先可见性、宿主是否最小化、当前是否使用该预览、是否关闭/失败；最小化不能靠 `Visible` 判断。
2. 不具备呈现资格时暂停定时调度；保留可复用会话，正常隐藏不反复销毁设备。
3. 恢复时重置帧调度基准，按当前 DPI/尺寸和最新主题提交场景后再出帧，不补跑后台帧。
4. 明确订阅宿主 `Resize/VisibleChanged/ParentChanged` 等事件的所有者，换父窗及 Dispose 时注销。

**回归**：实际 `Minimized` 后帧数停止；恢复后在有界等待内继续；连续 50 次隐藏/最小化/恢复，设备与事件订阅数量稳定；导出的一次性离屏快照不受普通呈现暂停策略阻断。

## 4. R2：实际路线、形态与导出一致

建议在现有预览层引入一个小的只读请求/结果模型，最终名称实施时确定：输入含文档修订、编辑目标、预览形态、DPI、设置快照；结果含实际路线、目标帧状态和失败原因。编辑目标是用户正在修改的字段集合，不能用它代替实际绘制路线。

### F04 / P2：所有 GPU 降级都使用同源回退派生

落点：[ThemePreviewControl](../../src/ThemeEditor/ThemePreviewControl.cs)、[LegacyFallbackStyleResolver](../../src/Rendering/LegacyFallbackStyleResolver.cs)。

- 显式兼容目标、GPU 开关关闭、安全模式、初始化失败、运行期故障，落入 legacy 时统一构造回退派生主题。
- 原生经典主题继续使用自身配置；不可把中性回退色套到经典主题。
- 清理重复映射或让生产桥与编辑器共享同一映射实现，保留告警色、进度语义、源字体所有权及未知字段。
- 生产路线、状态条与导出结果使用同一份“实际路线”结果；GPU 暂未首帧时显示准备中，不提前宣称成功。

**回归**：主色 `#112233`、回退色 `#AABBCC`，上述各路径的实际像素及结果均为回退色；源 JSON、源颜色和共享字体不被修改/释放。

### F05 / P2：降级不改变横向形态

落点：[ThemeStudioForm.RefreshPreviewNow](../../src/ThemeEditor/ThemeStudioForm.cs)、[ThemePreviewViews](../../src/ThemeEditor/ThemePreviewViews.cs)。

- GPU 横向初始化失败或运行期失败后，选择生产同源横向 GDI 渲染器，继续使用横向模拟指标与回退派生主题。
- 通过预览结果/事件通知工作室切换控件和更新状态；不要求用户额外点一下目标下拉触发纠正。
- 竖向、横向、任务栏各自保持形态；失败原因独立呈现，避免沿用隐藏控件的旧成功状态。

**回归**：初始不可用与运行中故障两种路径，验证布局列、实际绘制和截图；不能只断言状态文案包含“横向”。

### F06 / P2：任务栏预览消费当前设置的隔离快照

- 在创建及设置变更后调用现有 `ApplySettings`，输入来自传入工作室的当前设置快照，明确空输入时的默认模式文案。
- 复制布局与颜色字段并同步实际明暗；不持有可并发变更的全局设置引用，不调用静态 `ReloadStyle` 改生产任务栏。
- 同一份快照同时供任务栏布局测量与绘制，防止字体/行模式不同步。

**回归**：自定义标签色 `#123456`、单行、自定义字体和间距；明暗切换；设置变更后重开；预览前后生产样式完全一致。

### F09 / P2：实现真正的任务栏效果图导出

落点：[ThemeExportService](../../src/ThemeEditor/ThemeExportService.cs)、工作室导出入口。

1. 本计划选择**补齐任务栏导出**，不是继续映射为竖向。将“形态”独立于“GPU/legacy/fallback 路线”，演进现有方向参数时保留旧调用兼容入口。
2. 使用 `HorizontalLayout` 的 Taskbar 模式与 `TaskbarRenderer` 的独立样式上下文，固定模拟数据、显式设置快照、明确浅/深背景。结果报告实际形态、路线和像素尺寸。
3. 任务栏不使用 GPU 主面板渲染器；颜色来自设置，主题只参与已有布局合同。
4. 原有竖向/横向投稿图合同保持兼容；投稿服务不因用户当前预览为任务栏就静默改变市场要求的默认图形态。

**回归**：任务栏单双行/明暗/自定义设置导出；像素尺寸与布局匹配；图中确为任务栏内容；文件失败如实报告；源主题、设置与生产样式不变。

## 5. R3：F02 / P1，真实加载与应用结果

主要落点：[ThemeManager](../../src/Core/ThemeManager.cs)、[AppActions](../../src/Core/Actions/AppActions.cs)、[ThemeStudioLauncher](../../src/ThemeEditor/ThemeStudioLauncher.cs)。承接原 E03，不另建设置分派器。

### 实施决策

1. 给主题加载增加可报告结果的入口：实际加载主题、请求身份、源修订/摘要、是否使用缺省主题及原因。保留启动时既有容错接口供旧调用使用；工作室显式应用不能把缺省加载当请求主题成功。
2. 加载结果由运行时持有/发布，路线查询读取该结果与呈现状态，不再次打开请求文件猜路线，也不为查询再分配一套运行期字体。
3. 采用分阶段结果：文档保存、Settings 持久化、主题运行时提交、菜单/任务栏等附属模块、首帧准备。记录每阶段状态和当前实际主题，字段命名对齐 E03 的修订与模块结果。
4. 默认采用**如实报告部分成功**：主题已切换但附属模块失败，保留真实状态并提供重试失败模块；不把所有异常自动恢复 `Skin` 并声称旧主题仍在。
5. 新主题提交前失败可保留原运行主题。需要恢复旧主题时显式调用应用编排并等待结果；恢复失败也必须报告，不能回退一个字符串代替运行时动作。
6. 缺失/坏 JSON 提前失败时保持旧运行主题；磁盘保存结果与期望配置保留情况写清楚。运行时对象的展示名不能代替文件身份，使用规范主题 ID 加修订/摘要。
7. GPU 首帧未完成、窗口隐藏等待首次显示时用 Pending，界面继续接收完成/失败事件；等待超时是 Unknown/Pending，不伪装回退成功。窗体关闭取消自己的等待，不取消已提交的全局应用。

### 验收矩阵

| 注入条件 | 必须看到的结果 |
|---|---|
| Settings 写入失败 | 不调用运行时应用，内存期望值按保存合同恢复 |
| 请求文件缺失或坏 JSON | 请求应用失败；实际主题身份仍可确认，不称其已生效 |
| 同名主题修改后应用 | 新修订或摘要进入运行时，后续帧使用该修订 |
| 主题提交成功、菜单或任务栏失败 | 部分成功；实际主题为新主题；明确失败模块可重试 |
| GPU 首帧失败 | 记录真实回退路线及原因，呈现结果不宣称 GPU 已就绪 |
| 显式恢复旧主题再次失败 | 两次操作结果均保留，实际状态不猜测 |

先用窄的加载器/模块动作/呈现事件接缝做故障注入，再走真实主窗体入口验收。不能只让 Fake Gateway 返回期望值证明闭环。

## 6. R4：F10 / P2，VPS 凭据头与动态主机授权

落点：[PluginProcessor](../../src/Plugins/PluginProcessor.cs)、[PluginExecutor](../../src/Plugins/PluginExecutor.cs)、插件设置与当前未跟踪的 [vps_traffic.json](../../resources/plugins/vps_traffic.json)。实施时确认该模板的归属和当前版本，不覆盖并行编辑。

1. 将 `X-API-Token` 纳入真实凭据头分类；对初始请求、缓存命中/在途复用、逐跳重定向采用一致判定。
2. 支持用户自建主机，但授权必须由应用界面的用户操作产生，存入主程序管理的实例授权记录，插件 JSON 不能自授。
3. 为新动态主机路径使用精确 origin（HTTPS、规范化 IDN 主机、有效端口）授权，关联插件实例与目标；不能用任意主机、通配符或“整个实例的所有 URL”替代。旧字面量主机插件的既有合同单独保持兼容。
4. 用户填写/修改主机和令牌后，保存界面清楚展示令牌去向并记录所确认 origin；新目标、更改主机/端口或导入配置不能自动沿用其他目标授权。此处是待实现的产品交互，不是本次写计划另行要求用户确认。
5. 初始目标与每次跳转均复核；未授权不发送凭据。凭据分类修正后若模板尚无有效授权，应显示需要配置，不静默变成永远无数据。
6. 设置和诊断中不打印令牌；沿用已有 DPAPI 字典保护。输入掩码若补充，要落实到真实编辑控件，不能只把模板 `type` 改为未实现的 password。

**回归**：虚构令牌+本地测试服务器，覆盖已授权目标、未授权目标、跨目标复用、HTTP 降级、不同端口、IDN/大小写规范化、重定向、导入后未确认和删除实例。未经授权服务器收到的带凭据请求数必须为 0；不访问用户真实 VPS。

## 7. R5：F03 / P1，真实资源门禁及测试线程收口

1. 沙箱设置显式启用 GPU；真实 GPU fixture 同时证明设备创建和首帧成功，实际运行 DPI、主题、驱动和设备信息进入证据。
2. 无可用 GPU 的机器可完成纯规则与降级测试，但 GPU 门禁标为未验证。必跑 GPU 的验收 runner 遇到能力不满足直接失败；不能用降级执行代替通过，也不能依赖测试顺序遗留的全局开关。
3. 200 次真实目标切换中，每次回到主效果都确认该修订成功出帧；兼容目标确认实际绘制与 GPU 停帧。记录真实设备创建、GPU ledger、句柄/GDI/USER、稳态采样序列及关闭后归还情况。
4. 在相同配置下先预热再采样，采用有解释的稳态斜率和关闭后资源所有权检查。阈值基于基线测量制定，不能单纯抬高到本次结果以上；低于阈值也不等于已证明所有资源归属。
5. 修复 `RunSta` 未检查 Join 结果。短测试超时明确失败；长期压力场景使用受控独立进程，超时只结束该场景自有进程并收集证据，不能遗留继续改全局目录的线程或终止别人的 testhost。
6. 对 Settings 单例、目录、启动 guard、静态事件等接缝采用成对恢复。不同会话不并行跑 LHM/硬件全量套件；隔离输出使用项目支持的 `BaseOutputPath`，Host 显式绑定同轮产物。
