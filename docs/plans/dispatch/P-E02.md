## 任务（§6 逐条）

1. **命令面实现（管道侧）**：`ApplyConfigAsync`（命令应答/超时/取消；仅相同 revision/内容可合并，不同版本排队或明确被取代）、`RequestSamplingAsync`（=既有到期采样合并语义）、`RequestFullRescanAsync`（独立操作 ID、有界、`HardwareOperationResult` 状态机 Queued/Running/Completed/Failed/Cancelled/Rejected）、`SubmitDemand(consumerId)`/`ReleaseDemand`（管道协议消息演进——IpcMessages 演进须兼容现有帧：新增类型/字段，不改旧含义，协议次版本演进）。
2. **进程内对照**：适配器侧实现归 P-E01——你的语义一致性测试经 `IHardwareClient` 接口对两种客户端跑同一用例集；适配器行为不符处**写报告**，由集成人转 E01，不直接修。
3. **超时语义**：调用方超时 ≠ 底层取消；超时的非幂等操作保留有界操作记录（容量+截止期限），新请求取得明确 busy/operationId，不立即重复重扫。
4. **取消语义**：一个加入者取消不取消共享操作；取消底层执行由操作所有者发起并报告是否支持。
5. **容量与截止期限**：请求队列/待应答表/执行记录全部有界；超限返回可解释 Rejected，不无限 Task.Run、不静默丢配置。
6. **重连重放**：Host 重连（监督器新会话）后客户端重放最新期望配置与有效需求；旧会话应答不能完成新命令（session token 校验已有，补命令面）；只有实际应用版本确认后才把该版本读数标为当前有效。**SessionEpoch（复审必改4）：Host 重启/重连时快照 SessionEpoch 递增、旧会话快照数据不混入新会话（与 E01 语义一致，语义一致性测试覆盖）；同时实现 E00/F2——`OnSessionClosed` 重置 `_lastBatchId`。**
7. **UI 同步等待修复**：`ThemePreviewService.cs:146` 的 `GetAwaiter().GetResult()` 改真异步（下载改 async 路径，UI 不阻塞）；此为本包唯一 UI 文件改动。
