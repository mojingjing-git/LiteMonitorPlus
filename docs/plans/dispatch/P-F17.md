## 缺陷描述（协调者已复现并定位到行）

**症状**：`tests/LiteMonitor.Tests/ReviewMarketPersistenceRegressionTests.cs` 在全量跑时**间歇失败**（实测命中概率约 1/3），失败断言为：

```
System.UnauthorizedAccessException: Access to the path is denied.
   at System.IO.FileSystem.MoveFile(String sourceFullPath, String destFullPath, Boolean overwrite)
   at LiteMonitor.src.Plugins.PluginMarketInstallCore.CommitInstall(...)
```

**根因**：Windows 上 `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING)` 要求对**目标文件**具备 DELETE 访问权；而读取侧用 `File.ReadAllBytes`（以 `FileShare.Read` 打开，**不共享 Delete**）读目标文件 ⇒ **并发读取者存在时，原子替换直接返回 Win32 `ERROR_ACCESS_DENIED`**。

**真实用户影响**（不是测试专属）：`CommitInstall` 先写写前日志（`:1028`）再原子替换（`:1038`）；若**恢复线程**在这两步之间读到该日志并读取目标文件，就会与自己的替换相撞 ⇒ 安装**静默失败并留下事务日志** ⇒ 下次启动被回滚 ⇒ **用户的安装丢失且没有明确报错**。

**证据锚点（`src/Plugins/PluginMarket.cs`，行号已核实）**

| 行 | 代码 | 角色 |
|---|---|---|
| `:522` | `actual = ComputeSha256(File.ReadAllBytes(path));` | 读取侧（目标可用性校验） |
| `:1542` | `try { return File.ReadAllBytes(logPath); }` | 读取侧（写前日志留证） |
| `:1652` | `ComputeFileSha(string path) => PluginMarket.ComputeSha256(File.ReadAllBytes(path));` | **读取侧核心** |

## 实施要点（用户已裁定的修法：**根因 + 兜底都改**）

### ① 读取侧：让并发替换不再被阻塞

把目标文件的读取从 `File.ReadAllBytes`（`FileShare.Read`，不共享 Delete）改为**共享 Delete** 的读法，例如

```csharp
new FileStream(path, FileMode.Open, FileAccess.Read, FileShare.ReadWrite | FileShare.Delete)
```

读出字节后计算摘要。覆盖 `:522` / `:1542` / `:1652` 三处。

⚠️ 保持既有语义：`:522` 外层的 `catch { actual = ""; }`（读不到就当不匹配）**不要改成抛异常**；`ReadLogBytes` 的 `catch { return null; }` 同理。

### ② 替换侧：有界重试（符合「恢复有界」）

`File.Move(..., overwrite: true)` 在 `UnauthorizedAccessException` / `IOException` 上做**有界重试**：

- 最多 N 次（N 取 3～5），**总预算**用**可注入的单调时钟**控制，**禁止无限循环**、禁止写死 `Thread.Sleep`。
- 预算耗尽仍失败 ⇒ 抛出**可识别**的异常（带明确原因，例如"目标文件被占用，无法原子替换"），并**走既有回滚路径**，**不留半成品**（stage / backup 清理干净，记录与文件保持一致）。
- **禁止**把"重试耗尽"吞掉伪装成成功。

### ③ 事务语义不变

落盘顺序保持"写前日志 → 同目录暂存（同卷）→ 备份旧内容 → 原子替换 → 更新安装记录 → 清理备份与日志"；回滚承诺（"不留半截插件文件、记录与文件不一致"）必须保持。主题市场复用同一核心（`ThemeMarket.cs:156` 先对账再安装），修一处两条线都受益。
