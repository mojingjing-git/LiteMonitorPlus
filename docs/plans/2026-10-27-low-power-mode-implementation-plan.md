# 实现计划 4：低功耗模式

- 日期：2026-10-27。
- 状态：待实施；分“显示/动画调度”和“多消费者采样频率”两个可独立验收阶段。
- 前置：[修复计划](2026-10-27-p1-p2-remediation-plan.md) F07/F08/F11；[趋势与告警](2026-10-27-trends-alerts-implementation-plan.md)时效合同；[场景配置](2026-10-27-scenario-profiles-implementation-plan.md)的期望/实际配置边界。
- 协同：[诊断中心](2026-10-27-diagnostics-center-implementation-plan.md)、[总索引](2026-10-27-repair-and-product-roadmap.md)、E01/E02/E04。正式隔离完成后需重新测两进程总开销，不能用 I2 双采集原型宣称最终省电。

## 1. 用户目标

减少不可见窗口和无需求数据的后台工作；电池供电时降低装饰动画开销，同时保住用户已经启用的告警、历史和有效网页连接。

设置提供“关闭 / 自动 / 节能”三种模式。首版默认关闭以保持旧行为；隐藏与最小化停帧属于基础正确性，关闭省电也不能继续无意义出帧。自动模式根据可靠的电源状态启用显示预算，未知供电状态保持常规策略并给出说明。

界面显示当前有效策略与主要原因，例如“节能：动画上限 10 FPS；采样仍为 1 秒，因为温度告警需要”。不宣称未经测量的电池续航提升百分比。

## 2. 现有基础与关键缺口

| 现有实现 | 计划处理 |
|---|---|
| [FrameScheduler](../../src/Rendering/Gpu/Effects/FrameScheduling.cs) 支持 1–240 FPS、Reset | 暂停为独立状态，不能把 0 FPS 塞进当前构造/更新接口 |
| [GpuPresentationHostController](../../src/Rendering/Presentation/GpuPresentationHostController.cs) 有 Suspend/Resume 类生命周期 | 显示策略调用既有生命周期，沿用窗口/捕获清理合同 |
| [HardwareSamplingCoordinator](../../src/System/HardwareServices/HardwareSamplingCoordinator.cs) 单飞、动态周期、最小 1000ms | 保留唯一采样入口、不补跑；由有效频率提供者供周期 |
| [DemandRegistry](../../src/System/HardwareServices/DemandRegistry.cs) 聚合布尔需求 | 当前无法表达消费者各自最大采样间隔，需要显式演进 |
| [SamplingDemand / SamplingConfig](../../src/Contracts/SamplingModels.cs) 和两种客户端 | 本地/IPC 统一传递有效周期与版本，不让主进程口头降频而 Host 仍按旧周期工作 |
| `UIController` 同时承载显示刷新及部分历史/告警逻辑 | 首先把必需后台业务从窗口刷新生命期移出，再暂停显示 Tick |

## 3. 三层策略分别计算

1. **采样层**：什么时候真正读取硬件，受告警、历史、有效 Web 和传感器窗口的时效需求约束。
2. **数据展示层**：什么时候格式化数字、刷新图表/任务栏；数据不变和窗口不可见时合并更新，但不改变原样本时间。
3. **装饰层**：GPU 材质动画、过渡、背景捕获的呈现预算；可以降帧/暂停，不必同时降低采样。

用户设置与主题文件只保存期望值；拟新增纯规则 `PowerPolicyResolver` 一类策略函数计算临时有效预算。场景提供基础偏好，电源/可见性在其上施加运行时限制，不改写场景、主题或 `Settings.RefreshMs`。

## 4. P-A：显示与动画调度

此阶段可先交付，不宣称已经实现采样省电。

| 情况 | 首版有效行为 |
|---|---|
| 常规、窗口可见 | 沿用用户刷新偏好和主题 FPS 上限 |
| 自动模式、电池供电、窗口可见 | 动画上限建议 15 FPS，取用户目标与预算较低者 |
| 手动节能、窗口可见 | 动画上限建议 10 FPS，可配置减少装饰动画 |
| 数据未变、材质无运动/无捕获变化 | 合并绘制，仅主题/数据/尺寸/曝光等失效事件触发必要帧 |
| 某窗口隐藏、最小化或不再是当前编辑目标 | 该窗口暂停绘制；其他可见窗口继续 |
| 锁屏/会话断开 | 暂停不可见呈现，采样需求另行计算 |
| 恢复显示或 DPI/尺寸变化 | 合并成一次最新状态提交，重置调度基准再呈现，不补历史帧 |

实施要求：

- 主窗、主题工作室、任务栏、趋势窗分别有呈现资格；不能以主窗隐藏直接暂停所有窗口。
- 数字展示、布局失效和 GPU 动画分开。静态材质仍必须在新样本、主题修订、窗口曝光时正确重绘，不能因省电变成冻结画面。
- 使用既有合并/防抖机制保留最新请求，队列有界；更新后依然验证目标修订成功帧，保留 F11 的代次约束。
- 捕获暂停/恢复复用既有单一所有者、WDA 清理账本和受控重建，不在每次可见性变化重复创建抓屏会话。
- 暂停有事件驱动的恢复条件，不靠高频 8ms Timer 反复检查可见性；保留真正需要的低频恢复/窗口维护任务。
- 电源状态变化去抖，普通预算切换建议稳定 2 秒后生效；窗口隐藏暂停及紧急需求提升不等待该去抖。

## 5. P-B：多消费者采样频率协调

### 频率需求合同

在现有 keyed demand 上增量表达消费者身份、是否活跃、最大可接受采样间隔、硬约束/可降级性和原因。最终模型名开工核定；不把新字段偷偷塞进现有布尔值含义。

| 消费者 | 生命周期与约束 |
|---|---|
| 主窗/任务栏 | 各自可见时登记；普通显示频率可受用户选择的节能预算调整 |
| 已启用告警 | 应用级登记，不依赖窗口可见；最大间隔与规则连续性预算匹配 |
| 长期历史 | 保持已配置记录口径；当前约 10 秒的取样不能被省电悄悄改成分钟级 |
| 明细趋势 | 可见窗口或用户明确启用的后台明细登记；被允许降频时页面说明分辨率变化 |
| 有效 Web 会话 | 延续认证和有效需求规则；不能因未授权请求增加采样，也不能因本地隐藏清空它 |
| 传感器窗口 | 打开时登记，关闭释放；查询目录不是重新枚举硬件 |
| 诊断中心 | 默认只读缓存，不追加采样需求 |

聚合取所有活跃消费者所要求的**最短允许间隔**，再受采集层物理最小周期 1000ms 约束。节能只放宽明确可降级的显示需求，不能覆盖更严格的告警/Web 需求。无法达到要求时返回能力受限和实际周期，告警不靠插值伪造连续样本。

没有活跃采样消费者时不启动普通硬件采集；监督心跳、句柄恢复和退出维护保留自己的轻量调度，不借“维护”偷偷读完整硬件树。历史或告警仍启用时不属于无需求。

### 配置与 IPC

1. 有效周期由单一运行时协调点从“最新已提交用户配置 + 当前需求 + 电源策略”派生，沿现有 `ApplyConfigAsync` 队列提交；与设置页、场景应用共用版本与串行原则。
2. 记录独立的有效采样修订和策略原因，不让临时降频覆盖用户持久化修订。较旧应答不能覆盖较新期望，Host 重连重放最新派生结果。
3. 当前 [IPC](../../src/Contracts/IpcMessages.cs) 为 major 1 / minor 1。以新操作/DTO 做增量演进，更新双方的明确支持判定与版本检查；不改旧 submit-demand 消息的既有语义。
4. 本地/Host 两端运行相同频率语义测试。不支持新能力的旧对端保持原安全采样周期，界面说明只启用了显示节能；不得显示整个模式已应用。
5. 降频不请求 FullRescan，不切换磁盘/控制器探测模式，不重开设备；告警要求恢复更快周期时立即升频，普通降频可加最短稳定窗口防止来回重配。
6. 周期改变同步样本时效和告警允许间隔的判断依据，保留源年龄；休眠恢复、断连期间不能拿旧值当新的有效采样。

## 6. 默认策略与开销边界

- 自动/节能首版主要降低装饰帧及可降级显示需求；插件仍按自己的已声明周期运行，不越过插件最小周期，也不宣称已优化插件轮询。
- 不修改 Windows 电源计划，不自动授予驱动/捕获权限，不通过强制 GC 或工作集裁剪伪造内存优化。
- 无设备拓扑变化时，省电模式切换的设备 Open/Close 和显式 Rescan 次数应为零。
- 每次策略决策只在输入变化时产生，重复相同状态不重复下发配置。诊断中心展示期望/实际预算、阻止继续降频的消费者及最近失败。
- 系统电源/会话事件订阅由应用级所有者持有，窗体订阅自己的可见性；关闭与卸载策略时成对释放。

## 8. 验收矩阵

| 场景 | 必须验证 |
|---|---|
| 主窗最小化、任务栏仍可见 | 主窗帧停止，任务栏数据正常 |
| 所有显示隐藏、告警启用 | 告警时效保持，不因无画布停采 |
| 本地隐藏、授权 Web 活跃 | 网页按有效需求更新，匿名访问不能提频 |
| 只剩长期历史 | 不无故按高帧率呈现，历史记录口径保持 |
| 全部采样消费者释放 | 普通采集次数不增长；维护/退出仍能完成 |
| 电池/交流/未知切换 | 策略稳定、可解释；未知状态不误当低电量 |
| 修改场景与节能同时发生 | 最新用户配置有效，临时预算不写回场景/主题 |
| Host 断连、旧版本、重连 | 不猜成功，不重复采集，最新需求正确重放 |
| GPU 运行故障、DPI 变化、恢复显示 | 回退正确，恢复后目标修订出帧，无代次错配 |
| 高延迟采样超过目标周期 | 不并发补跑，不伪造样本，不形成忙循环 |

纯规则采用假时钟；GPU、锁屏/恢复、真实电源及多屏用实机验证。模拟 AC/DC 不能替代真实电源路径签收。

## 9. 性能测量和放行

每组同机先预热 2 分钟，测量 10 分钟，常规/节能分别至少 3 轮；固定主题、监控项、窗口尺寸、供电、驱动和配置摘要。测试场景至少包含 GPU 可见、静态材质、主窗隐藏、任务栏独显及 Web/告警约束。

采集进程 CPU 时间、定时唤醒、真实呈现帧、GPU 占用/引擎、捕获帧、采样次数/耗时、样本年龄、私有字节、句柄及设备开关计数。Host 模式按主/子进程合计；CPU/GPU 下降不直接换算瓦数或续航，功耗结论需要相应硬件测量。

放行要求是：功能时效不退化、不可见窗口无持续出帧、无需求不进行普通采样、模式切换不重开设备、资源稳态无持续增长；设计为降低开销的场景在重复实测中确实减少对应工作量。若被告警/Web 硬需求限制，允许采样不降频，但必须如实解释，不能伪造整体节能数据。
