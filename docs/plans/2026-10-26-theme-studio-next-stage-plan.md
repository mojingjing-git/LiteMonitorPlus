## 5. N01：隔离任务栏预览样式

主要落点：[TaskbarRenderer](../../src/UI/TaskbarRenderer.cs)、[ThemePreviewViews](../../src/ThemeEditor/ThemePreviewViews.cs)、[ThemeStudioForm](../../src/ThemeEditor/ThemeStudioForm.cs)。

当前预览每次绘制装载模拟 Settings 的静态字体／颜色，生产任务栏绘制直接使用这些静态字段。仅在 FormClosed 恢复，不能覆盖工作室打开期间。

实施：

1. 将样式解析、字体所有权与绘制输入分开。预览持有独立样式上下文，生产保留自己的上下文；可用重载承接现有调用者，避免扩大改动面。
2. 使用同一绘制算法，但不在预览路径写入生产静态状态。不依赖“绘制前改全局、绘制后改回”作为最终隔离方案。
3. 自有字体按上下文释放；预览开关不释放生产字体，不重置用户自定义配色。
4. 样式隔离完成后移除工作室关闭时的恢复补丁。此项为代码级门禁：全局不再出现对生产任务栏静态样式的写入调用。
5. 保持事实文案：任务栏颜色由 Settings 驱动，主题参与布局；点选颜色也不能跳到错误的主题色字段。

自动化护栏（与人工验收同级，不得只做人工检查）：

- 在 TaskbarRenderer 增加 internal 只读样式快照（例如 CaptureStyleState()），供测试比较生产字体与四个颜色槽的当前值。
- 新增用例（可扩展 ThemeStudioPreviewFormsTests）：预置非默认生产字体与自定义配色 → 触发预览绘制 → 断言生产样式快照未变 → 关闭工作室后再断言同样未变。
- 覆盖两个预览实例交替绘制、浅深背景切换、重绘与隐藏。
- 危害说明：预览若写回生产静态状态，会释放用户自定义的任务栏字体并替换配色，表现为“工作室打开期间用户自定义任务栏字体失效”，不只是颜色不一致。

验收：先设非默认生产字体与自定义配色，分别在预览打开、切换浅深背景、重绘、隐藏、关闭和导出时检查生产任务栏。打开期间即须不变，并覆盖两个预览实例交替绘制。人工检查与自动化用例同时通过才算完成。

## 6. N02：GPU 会话复用与统一输入

主要落点：[ThemePreviewControl](../../src/ThemeEditor/ThemePreviewControl.cs)、[GpuThemePreviewControl](../../src/ThemeEditor/GpuThemePreviewControl.cs)、GpuSceneRenderer。

建立最小的预览请求／更新合同，包含文档 revision、编辑目标、视图、模拟输入、固定背景、尺寸、DPI、动画时间及失效代次。接口服务于现有预览，不建立通用渲染框架。

- 颜色、字体、参数与数据变化按实际需求更新材质／前景／场景资源，避免每次 SetTheme 都 Dispose/new 控件与 D3D 会话。
- 尺寸与 DPI 按交换链和字体资源需要更新；材质、设备或原生句柄变化允许有理由的受控重建。
- 保存防抖作为事件合并机制，但不能把防抖视作会话复用已经完成。
- 每次更新／重建记录原因与计数；快速修改后只提交最新代次，旧异步结果不覆盖新文档。过期判定统一以“代次号 + IsHandleCreated／IsDisposed”为准，不按时间窗或引用计数猜测；测试用可控假渲染器断言过期结果被丢弃。
- 处理隐藏、最小化、HandleDestroyed／重建、设备丢失与关闭。先停调度再释放自有资源；不跨线程访问 WinForms 控件。
- 继续隔离预览 guard 与生产 guard，不清理生产标记。一次性导出 guard 的重试也要有界，避免同一失败环境无限重复初始化；正常可见预览不逐帧新建 guard。
- 固定输入、captureRequested=false，不创建捕获或硬件采集源。

验收：对同一控件连续编辑参数、字体、布局，检查设备／会话创建计数、更新代次和输出；再验证真正需要重建的路径。主面板 GPU 与预览同时运行，双方关闭／失败不破坏另一方。

## 13. N09：TE08 后半、GPU 资源与 G6

在 N01～N08 稳定后的实际集成产物上执行，按 N00 冻结的环境串行运行。本项独占机器与全套件，按 §3.4 排期；测量期间不得改动测试文件或产品代码，报告须绑定唯一提交。

### 必测场景

| 场景 | 规模与重点 |
|---|---|
| G6 原经典场景 | 开关工作室 50 次、编辑 1000 次；保留冷启动／稳态分段 |
| G6 真实目标切换 | 主效果↔兼容外观 200 次，不以主题切换替代 |
| GPU 稳态与复用 | GPU 主面板与工作室并行；参数编辑、竖横切换、截图导出与关闭 |
| GPU 异常生命周期 | 初始化失败、设备丢失、句柄重建、隐藏／最小化、跨 DPI、重试与清理 |
| 样式隔离 | 实际任务栏与预览／导出并行，生产字体和自定义色不变 |
| 导出压力 | 多次导出／资料生成，含取消与失败，检查旧文件和临时资源 |

同时观察 Private Bytes、GDI／USER、句柄类型、线程／定时器、GPU ledger 与设备／会话创建计数；不只依赖 GC 后的总计数。固定稳定窗口与可接受噪声，超标先定位，不在看到结果后放宽阈值。

对冷启动约 +110 句柄进行归因：比较最小窗口、资料库／检查器、经典预览、GPU 会话、导出及关闭后的差分，结合句柄类型与必要的跟踪，区分进程级一次初始化、延迟回收、仍存活资源与真实遗留。不能仅因曲线平稳就宣布全部资源正确释放。

归因判据（先定判据再看数，不在看到结果后改判据）：

| 观测结果 | 判据 | 结论 |
|---|---|---|
| 同一配置重复 3 次启动的差值 ≤ 噪声阈值 X | 差值不随轮次累积 | 进程级一次初始化 |
| 句柄／GDI 随轮次线性增长，且 GC 后托管存活集同步增长 | 两项同步上升 | 真实遗留，按存活对象类型定位 |
| 托管存活集平稳，Private Bytes 线性增长 | 仅私存上升 | CLR 堆页保留，按既有基线归类，不判为泄漏 |
| 句柄数先升后稳且与最小窗口差异固定 | 关闭后回到基线 | 延迟回收 |

X 取同一配置重复运行的抖动上限，取值写入报告。

交付报告包含：

- 与历史经典参考分列的集成后数据，补齐真实目标切换与 GPU 路径。
- 输入至最新有效画面的延迟和会话创建次数；沿用总计划 P95 ≤ 100 ms 等目标，解释环境条件。
- 冷启动归因、稳态趋势、关闭后的所有权核对，以及失败／跳过／未验证项。
- 实际命令、提交、产物摘要、驱动与显示条件、原始输出和截图。
- 单次串行全量回归与主题专项结果；精确分开发现、执行、通过、失败、跳过数量。

GPU 实测、G6 或必需 DPI 组合缺失时，可以交付阶段报告，不能放行最终验收。
