# 主题工作室后续优化意向计划

- 日期：2026-10-26。
- 状态：意向储备；待当前批次完成后，结合实际使用再细化。
- 前置：[下一阶段计划](2026-10-26-theme-studio-next-stage-plan.md)的预览、应用、导出、实机与资源验收收口。
- 产品约束：沿用[主题工作室重做计划](2026-10-26-theme-studio-rebuild-plan.md)及[TE00 能力合同](../design/theme-studio/TE00-capability-contract.md)。
- 本文只记录目标、候选范围、优先顺序及后续决策依据，不冻结技术接口、工期、任务分工或验收阈值，也不启动实现。

## 1. 优化方向

当前批次完成后，主题工作室的后续重点是提高制作效率、帮助用户判断修改效果，以及减少难读、溢出和跨环境表现不佳的主题。

继续保持苹果风格工作区与 Windows 原生窗口栏。复用已经建立的文档历史、属性能力表和生产渲染路径，避免每增加一个功能就再建设一套编辑／渲染机制。

当前批次遗留的正确性、保存可靠性、预览路线或资源问题，仍在原实施任务中处理，不用本意向计划替代其验收。

## 2. 候选范围与顺序

下表是后续评估顺序，不是缺陷严重度，也不表示所有项必须同时进入下一轮开发。

| 编号 | 方向 | 建议顺序 | 主要价值 |
|---|---|---|---|
| O01 | 残留的生产布局裁切 | 存在则优先处理 | 改善实际显示，并与预览保持一致 |
| O02 | 修改前后对比 | 优先细化 | 让字体、间距、配色和材质变化更容易判断 |
| O03 | 主题体检 | 优先细化 | 提示可读性、溢出、字体和兼容表现问题 |
| O04 | 模板与样式预设 | 第二组候选 | 降低从零制作与搭配样式的成本 |
| O05 | 批量调整与样式联动 | 第二组候选 | 减少重复操作，保持多处样式一致 |
| O06 | 资料库管理 | 随主题数量增长评估 | 提高查找、辨识和维护主题的效率 |
| O07 | 完全独立的兼容字体与布局 | 长期候选 | 满足两种外观需要不同排版的真实需求 |

## 3. 优先细化的方向

### O01：残留的生产布局裁切

若当前批次之后仍有末列、长标签或宽数值裁切，应作为生产布局缺陷跟踪，先定位测量、布局和裁剪的责任边界，再让生产与预览共同受益。

后续细化需提供可复现的主题、输入、DPI、视图及对照画面。不能只给预览添加偏移来隐藏问题；若当前批次已经修复，则记录修复与回归结果，不重复立项。

### O02：修改前后对比

让用户在同一主题、输入场景、背景、DPI、尺寸和动画时刻下，比较已保存版本与当前草稿。

候选交互从简单的原版／草稿快速切换开始，再根据使用效果决定是否需要并排或分割对比。对比时保留画布缩放与观察位置，减少“画面变了但不知道哪里变了”的困扰。

主效果与兼容外观分别比较，标明对比基线；不将跨路线、跨场景的两幅画面当成修改差异。比较操作只改变视图，不应用主题、不改草稿、不新增历史事务。

后续需要决定：比较基线如何选择、未保存新文档如何处理，以及并排呈现是否值得额外的渲染资源。

### O03：主题体检

在现有字段合法性校验之上，帮助用户发现实际画面的质量问题，而非再做一遍配置校验。

优先考虑：

- 正文、次要文字、数值与背景的可读性。
- 标题、标签、单位、数值的溢出或裁切。
- 字体缺失、实际替代字体与字符显示异常。
- 正常、告警、危险与无值状态是否容易区分。
- 兼容外观在代表性场景中是否仍然清晰可用。

体检结果应能定位到具体对象和相关属性，解释判断条件，允许用户忽略。调整由用户决定，不自动改配色、替换字体或覆盖配置。

透明、玻璃材质的可读性受背景影响。可先针对固定的浅、深、复杂背景检查，并标明测试条件；不能保证对任意桌面都满足同样结果。尚不能可靠判断的项目显示限制，不输出虚假的确定结论。

后续需要决定：首批检查项目、误报处理、显示时机、性能预算，以及哪些结果只是建议、哪些属于既有的真实错误。

## 4. 第二组候选

### O04：模板与样式预设

区分两种用途：

- 模板：用于新建文档，例如紧凑、大字号、高可读性等起点。
- 样式预设：在现有主题中应用一组协调的配色、字体或间距。

预设必须遵守当前材质、编辑目标与共享字段能力。应用前说明影响范围，作为一次可撤销修改，不暗中切换 backend、开启 GPU 或改变运行中主题。

是否进入开发，以实际制作时“从零起步困难”或“搭配耗时”的案例为依据。预设数量、内容与存储方式留到细化阶段决定。

### O05：批量调整与样式联动

面向重复工作：统一数值字体、分组间距、相同角色的配色，或将一组修改应用至明确选定的对象。

先观察现有属性是否已经按角色共享，避免给本来一次就能完成的操作另做批量入口。新增功能需展示修改范围，尊重独立覆盖与共享关系，并支持一次撤销。

后续重点评估“选择一组对象后批量修改”与“长期绑定为同一种样式”的复杂度。可以先解决批量修改，不必同时引入新的样式继承体系。

### O06：资料库管理

根据真实主题数量，评估缩略图、搜索、收藏、排序，以及来源、版本、本地修改状态的展示。

来源与安装状态依据现有记录，不根据文件名猜测；记录不足时如实显示未知。收藏与排序属于编辑器偏好，不写进主题。

缩略图复用现有导出／预览能力，按内容变化更新；主题数量增加时保持打开、滚动和搜索流畅，不为每个列表项常驻一个 GPU 会话。

后续决定首批真正有用的筛选维度，以及缓存失效、离线表现和市场主题本地修改的呈现方式。

## 5. 长期候选：O07 完全独立的兼容样式

目前兼容外观有六个独立配色字段，字体与布局仍存在共享关系。只有在真实主题案例证明这种共享妨碍创作时，才细化完全独立的兼容字体与布局。

评估范围必须同时包含文件格式、缺省／继承、旧主题加载、生产与预览解析、市场校验、导出、撤销及迁移。不能只给编辑器加几个字段，让旧运行时继续忽略。

本意向不预定新字段名、schema 版本或迁移方案。先比较扩展带来的收益与长期维护成本，再决定是否立项。

## 6. 细化前需要收集的依据

当前批次完成后，使用已有能力完成几种真实创作流程：修改旧经典主题、制作或调整 GPU 主题、调校兼容外观、导出并准备投稿。

记录：

- 哪些效果最难判断，是否需要反复保存、应用或截图才能比较。
- 哪些错误直到应用后才发现，能否由可靠的体检提前识别。
- 哪些修改频繁重复，实际涉及几个字段或对象。
- 主题增多后查找与辨识是否成为问题。
- 共享字体／布局是否有具体受限案例。
- 是否仍有生产布局、性能或资源问题需要先修。

使用样例和复现步骤作为优先级依据，不预设全部候选都必须实现。收集过程不要求新增遥测或云服务。

## 7. 建议的后续决策

1. 当前批次按既定范围验收，剩余必需项继续留在原任务下。
2. 复核 O01；若有真实生产缺陷，先单独修复。
3. 优先细化 O02“修改前后对比”与 O03“主题体检”，形成一个范围受控的体验改进包。
4. 根据使用记录，再选择 O04～O06 中收益最高的一项或少量项目。
5. O07 保留为格式演进候选，不与前几项默认捆绑。

进入具体细化时，重新阅读实际代码与当前完成记录，确认是否已有等价能力，再补用户流程、技术方案、依赖、工作量和验收标准。本文届时更新为已选范围，或链接独立实施计划；未选项目继续保留为意向。
